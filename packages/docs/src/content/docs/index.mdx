Framework Tracker compares the real cost of building with modern web frameworks. It looks at what developers inherit when they start a project and what users and servers experience when it runs.

The goal is to make the trade-offs easier to see and help framework authors iterate and improve each meta-framework. Buidling on the E18E’s mission to improve the JavaScript ecosystem.

It's an ever-growing list of tests that we will add to with community support.

If you find an issue with a test or have an idea for new ones, please open an issue in our repo: [Framework Tracker Github Project](https://github.com/e18e/framework-tracker/issues)

## What we measure and how

We currently split our tests into two sections: Dev Time and Run Time. Dev Time tests use a starter project set up with the meta-framework’s CLI or documentation, following the default or recommended setup. Runtime tests use a small app project set up for the measurements. We currently measure:

### Dev Time

- [Dependency counts](/dev-time/#dependency-counts)
- [Node Modules Size](/dev-time/#node-modules-size)
- [Build and Install Times](/dev-time/#build-and-install-times)
- [Dev Server Startup](/dev-time/#dev-server-startup)
- [Core-JS Polyfills](/dev-time/#core-js-polyfills)
- [Browser Baseline](/dev-time/#browser-baseline)
- [Minimum Node Version](/dev-time/#minimum-node-version)

### Run Time

- [Lighthouse Client-Side Rendered](/run-time/#client-side-rendered-tests-lighthouse)
- [Lighthouse Server-Side Rendered](/run-time/#server-side-rendered-tests-lighthouse)
- [Initial Load](/run-time/#initial-load)
- [Server-Side Throughput](/run-time/#server-side-throughput-tests)
- [SSR Load Tests](/run-time/#ssr-load-test)
- [SS Framework Router Link Load Test](/run-time/#ssr-router-link-load-test)

### Core Web Vitals

- Largest Contentful Paint (LCP): [Desktop](/core-web-vitals/#desktop-lcp) · [Mobile](/core-web-vitals/#mobile-lcp)
- Cumulative Layout Shift (CLS): [Desktop](/core-web-vitals/#desktop-cls) · [Mobile](/core-web-vitals/#mobile-cls)
- First Contentful Paint (FCP): [Desktop](/core-web-vitals/#desktop-fcp) · [Mobile](/core-web-vitals/#mobile-fcp)
- Time to First Byte (TTFB): [Desktop](/core-web-vitals/#desktop-ttfb) · [Mobile](/core-web-vitals/#mobile-ttfb)
- Interaction to Next Paint (INP): [Desktop](/core-web-vitals/#desktop-inp) · [Mobile](/core-web-vitals/#mobile-inp)

Dev Time and Run Time tests run in the CI pipeline, and we save the results to a JSON file that the Astro docs site loads. The [Methodology](/methodology) page explains how we collect each metric.

We track metrics for all `major` and `minor` versions. Stats show the latest version we have. You can click into each Framework detail page to see changes over time
